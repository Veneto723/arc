# arc — architecture

On-demand depth for [`CLAUDE.md`](../CLAUDE.md). Read the section for the area you're touching; the always-loaded essentials and the two big gotchas live in CLAUDE.md and are not repeated here.

Everything is `src/*.js` — one focused module per file, no bundler, no TypeScript. `arc-runner.js` is the entry point (`arc.cmd` / `arc.sh` → `node arc-runner.js`).

---

## The account/session wrapper

- **`arc-runner.js`** — the launcher. Resolves which account to use (auto-selects the subscription while it has headroom, falls to the least-busy gateway only when it's exhausted; launch/resume only, never mid-session), builds the `claude` invocation, and handles **respawn** — a `switch`/`restart` relaunches the *same* conversation. `stripConvArgs` is load-bearing: on respawn it removes `--fork-session` (or the peer re-forks itself and abandons its history), `--continue`, and the birth prompt (or the peer re-submits its own claim forever). It strips the live `/arc-<verb>` spelling and retired `arc:<verb>` leftovers via arc-slash's own regexes (`SLASH_RX`, plus the strip-only `LEGACY_RX`).
- **`arc-config.js`** — config at `~/.claude/arc-config.json`; accounts, thresholds, features. A gateway key can be DPAPI-encrypted in-config, bound to the Windows login (`arc set-key <id>` to set/rotate). Config is backed up before every change. Also owns the **NTFS ACL boundary** for the credential profiles (Windows ignores mode bits, so the DACL is the only real one): `/inheritance:r` and `/grant:r` must be **one `icacls` call** — split in two, the directory has no ACEs between them and is unreadable to its own owner for ~32ms, which is a live session's `CLAUDE_CONFIG_DIR` and cost every session on an account its statusline.
- **`arc-profile.js`** — per-account profile isolation (each account gets its own `~/.claude` profile so logins/chats don't collide). Each synced settings key declares its own merge policy in the `ARC_SETTINGS_KEYS` table — `replace` (arc is sole author: `hooks`, `statusLine`), `union` (`permissions`: profile scalars win, allow/deny/ask lists union — **plus a retirement strip, because a union can add but never remove**, so a grant arc takes back would otherwise live forever in every profile), `overlay` (`skillOverrides`: profile wins) — and an unknown policy is *skipped*, never defaulted, and fails the suite. Root-only writes are ineffective in profiled sessions.
- **`arc-switch-core.js`** — the mid-conversation account-swap engine: the same chat continues on the other account, preserving model, permission mode, and effort. Also owns `/arc-peek`: a synchronously-refreshed usage snapshot (`[sub]`/`[gw]` rows, per-model 7d scoped limits with severity glyphs when the payload carries them, current account tinted rather than arrowed).
- **`usage-monitor.js` / `gw-usage.js`** — the statusline: subscription 5h/7d %, reset times, pace ETA; gateway accounts' real cost/tokens via a cached, zero-token metadata call.
- **`arc-update.js`** — the self-updater. A cached, fail-safe, bounded launch-time check against the repo's latest GitHub Release; `arc update` forces it; `arc release` is the gated dev-side publish. Everything on the launch path is fail-safe: any network/parse/FS error resolves to "no update" and launches normally.

## The coordination board

Independent `claude` sessions in one repo are **peers**; the append-only ledger is their only channel.

- **`arc-board.js`** — the data model. The ledger is `.arc/peer/notes.jsonl` (append-only, machine-local, gitignored). A note's identity is a stable `<origin>:<random>` id; its delivery order is a **per-origin `ord`** counted at read time. Because `ord` is scoped to one writer and git `merge=union` concatenates each side's lines without reordering, every machine counts the same ordinal for the same note — so a merged board delivers each note once with no skips or dupes. `origin.json` is the machine's identity and must **never** be committed or carried (two machines sharing an origin collide their ord streams). A **claim** (`claim-<role>.json`) is the pointer from a role to its conversation (`convId`) — the revive pointer. `isHolder` decides genuineness: a live pid whose process started *before* the claim's timestamp (Windows recycles pids, so a live-but-older-than-the-claim stranger would otherwise squat a chair). A **pid-less claim is a tombstone** — reads VACANT (`isHolder` requires a pid) but still carries the `convId`, so the chair stays revivable. Read the claim RAW (not through the genuineness filter) when you need the tombstone.
- **`arc-notes.js`** — the command handlers (`role`/`note`/`notes`), turn-start note **injection**, and the read cursor. Posting a note of **rank ≤ 1** also raises the interrupt flag (see `arc-alarm.js`) — one tunnel in, the kind decides how hard it lands. `arc role`'s roster shows each live peer's activity (`live · balanced · active`, plus a `↳ <age> ago:` line) read from `arc-feed.roleStateOf`, never re-derived; the age is the timestamp of the action itself, not of the last transcript write, because `active` spans 15 minutes and a bare "now" would understate staleness. Cursors and `seen-*` are per-role and machine-local; a note over ~7k chars spills to a `spill-<seq>.txt` delivery cache (regenerated from the ledger, so it never travels). Also computes the statusline's **DEAF badge**: role-holder + stale offer *or* stale unread (>90s, so arming windows never flash) **and** transcript quiet past the same threshold — `transcriptQuietFor` reads the conversation transcript's mtime, the one file that only grows during work, so a busy mid-turn session is never badged; an unresolvable transcript reads quiet-forever, fail-visible.
- **`arc-alarm.js`** — the **interrupt half** of a note. A rank ≤ 1 note writes `.arc/peer/alarm.json`, which the PreToolUse hook reads on every tool call; the gate denies that one call, hands the note over, and the peer re-issues. Entries are **addressed** (a directed note stops only its recipients — 176 of 183 such notes on the live boards are directed) and the file is an **index over the ledger, never a second truth**. Safeties: one read on the hot path (an absent flag ENOENTs and falls through), block-once per (session, note), **fail-open** if the ack cannot persist, a capped and untrusted-framed body, and a TTL past which an entry stops interrupting. Ceiling: nothing can interrupt mid-generation — of Claude Code's twelve hook events, `PreToolUse` is the earliest in-turn one, so a peer inside one long tool call is unreachable until it returns.
- **`arc-feed.js`** — a read-only `127.0.0.1` status feed for the **operator** (the human holds no role, so no other reader serves them): what every session is doing, across every repo, over SSE. Loopback-only with a Host allowlist against DNS rebinding. `VERSION` is load-bearing — a detached feed never reloads its source, so a snapshot **shape** change must bump it in the same edit or running feeds serve the old shape forever. Also the single home of `roleStateOf` (active/idle + what a session is doing), which `arc role` reuses so the peers and the operator cannot disagree. The WPF companion `scope/arc-scope.cs` renders it.
- **`arc-invite.js`** — spawning and reviving peers. **Birth** forks the caller (the newborn inherits the caller's transcript and must be told it is not the caller — the hook injects that identity correction on a fresh forked claim). **Revive** resumes the peer's own conversation via `--resume` (comes back as itself). A birth must not inherit `CLAUDE_CODE_*` / `ARC_SESSION`, or it never becomes its own session; the same strip drops `NO_COLOR` — the caller's tool subshell sets it and wt hands the new pane the invoker's env, which left every spawned peer rendering monochrome. `ARC_SPAWN_PROFILE=<name>` optionally dresses peer tabs in a named wt profile (`ARC_SPAWN_WINDOW`/`ARC_SPAWN_QUIET` are its siblings); unset stays profile-less on purpose — a guessed profile name is a failed launch on someone else's machine.
- **`arc-await.js`** — the listener. `arc join <role>` blocks in the background until a note lands, then exits — and *that exit is the wake* that re-invokes the idle session. `isWaiting` is a live-pid check on the await marker. Re-arming supersedes gracefully: `markWaiting` overwrites the marker with the new listener's pid, and the displaced listener notices the ownership change on its next poll and exits 0 without touching its successor's marker.
- **`arc-sync.js`** — export/import of sessions and the board across machines. Content (`notes.jsonl` + spills) travels; machine identity (`origin`, `claim` pids, cursors) does not — claims are tombstoned (pid stripped) at export, and a claim/cursor is only carried if its conversation actually landed at the destination root (checked through the same path canonicalization the board root uses, so short-name/junction spellings don't split one root into two).
- **`arc-done.js`** — derives task completion from **git evidence** (the commit), not the agent's word; hooked to `TaskCreated`/`TaskCompleted`.
- **`arc-postcommit.js`** — the commit broadcaster: wired as a repo's `.git/hooks/post-commit`, it turns every commit made from an arc session into a board note (attributed to the committer's role via `ARC_SESSION`; a no-op for non-arc commits, and it runs after the commit so it can never block or fail it).

### Note kinds — the kind decides how hard it lands

`info · request · result · correction · alarm · contract`, ranked in `KIND_RANK` (`alarm` 0 · `correction` 1 · `contract` 2 · `request` 3 · `result` 4 · `info` 5). The rank is not decoration: it orders the injection digest **and** decides the delivery channel.

**Rank ≤ 1 interrupts.** An `alarm` says work has stopped; a `correction` retracts something the recipient may be building on *right now*. Both are worthless if they arrive after the turn that needed them, so they also stop the recipient at its next tool call. Everything at rank ≥ 2 waits for a turn boundary — a channel that interrupts for routine news stops being read, and is then unavailable for the case it exists for.

There is **no `arc alarm` verb**; it was folded into the kind (one tunnel: you post a note). `blocker` was `alarm`'s first name and survives as a `KIND_ALIASES` shim beside `decision` → `contract` — 37 notes on the live boards carry it, and without the alias `normalizeKind` would degrade each to `info`, silently re-filing a stop-the-line as routine news. **Read the old spelling, always write the new one.** `arc <retired-verb>` refuses with the replacement rather than falling through to launching a session with your message as its prompt.

A **contract** is a thread, not a file class: an opener of kind `contract` plus every note replying to (or superseding) it. Membership is the opener's recipient list, changed only by superseding the opener; it is **settled** when every bound role has a live clause, and **withdrawn** when the opener is superseded by a `correction`. All of that is derived in `arc-board.contracts()` — no stored "closed" flag, because a declared flag is a second home for a fact the clauses already carry.

### Roles and the board vocabulary

The nouns are **BOARD** (a repo's shared ledger), **PEER** (another session on it), **ROLE** (a named seat with a committed charter in `.arc/roles/<role>.md`), and **CLAIM** (a session holding a role). Charters travel in git and outlive the session that wrote them; the board (`.arc/peer/`) is machine-local scratch and never commits.

## The hook layer

Three Claude Code hooks (wired into `settings.json` by **`arc-wire-settings.js`**) make the board and the zero-token command surface work *before the model runs*:

- **`arc-switch-hook.js`** (UserPromptSubmit) — matches command prompts (`/arc-<verb>` via `SLASH_RX` + an arg-policy gate — the ONLY prompt spelling; the retired `arc:<verb>` form is never matched here, its `LEGACY_RX` survives strip-only in `stripConvArgs`) and dispatches them in-hook at zero tokens; delivers waiting board notes at turn start; and stamps the HEAD the peer has seen (a turn-*start* lower bound for the next revive's catch-up brief). A successful *new* role claim is the one command that deliberately passes the prompt through and spends a turn — only the model's own background command can arm the listener, so a blocked claim would go idle deaf.
- **`arc-stop-hook.js`** (Stop) — feeds a peer's reply back at turn end (no keystroke) and nags an idle role-holder to arm its listener. (The DEAF badge is *not* here — `arc-notes.js` computes it, the statusline renders it.)
- **`arc-pretool-hook.js`** (PreToolUse) — the enforced gate, four rules: an empty-chair `arc delegate` is denied/asked/allowed by stance (a PreToolUse hook sees a tool call and can't tell the human's order from the agent's initiative, which is exactly why delegate has no prompt-command form); a `--board` note asks in *every* stance (leaving the repo is never pre-authorised); and a **verified reply** (`--reply-to` resolving to a note that genuinely reached this role, from the role being answered) is auto-*allowed* in every stance — a reply is not initiative, and gating it would put a permission prompt inside the auto-feed loop. and a live **alarm** addressed to this role denies one tool call so a busy peer reads it before proceeding (`arc note`/`arc notes` are exempt, or a peer blocked from reading an alarm could never clear it). Anything unproven defers to the normal permission flow.
- **`arc-slash.js`** — the single source of truth for the verb set shared by `SLASH_RX` and the strip-only `LEGACY_RX`, plus the `/`-menu skill stubs; `node src/arc-slash.js` regenerates the stubs, and a drift test asserts they stay byte-exact.

## Supporting modules

One line each — enough to know where to look; their own headers carry the depth.

- **`arc-bundle.js`** — discover/validate/install/remove self-describing add-on bundles (`bundles/`, `arc-bundle.json` manifests).
- **`arc-claudex.js` / `arc-claudex-proxy.js`** — the frozen "claudex" translator sidecar: lets Claude Code (Anthropic Messages API only) drive a GPT model served on the OpenAI Chat Completions shape.
- **`arc-comply.js`** — measures whether a prose rule is actually followed, by reading real transcripts. It is what turned "hooks enforce, prose asks" from a slogan into numbers (hook-enforced 98–99%, a prose rule 93–94%) and killed a planned hook on that evidence.
- **`arc-fieldguide.js`** — `arc fieldguide "<lesson>"`: a one-line gotcha left for whoever sits in this repo next, delivered on role claim.
- **`arc-profile.js` · `syncClaudeMd`** — `~/.claude/CLAUDE.md` is **not** read inside a profiled session: Claude Code reads `<CLAUDE_CONFIG_DIR>/CLAUDE.md`, and that is the profile. So `/arc-switch` used to drop the operator's global instructions entirely (measured 2026-08-07: four profiles on the machine, one had the file). `ensureProfile` now writes a single `@<canonical path>` import line into every profile, and keeps any profile-local rules below it. An `@import` rather than a hard link, by the operator's call — several accounts run at once and may edit the rules together, and a hard link is invisible, so a write-replace detaches one profile and the copies drift with nothing to show for it. Verified end-to-end with a headless `claude -p` at both project and profile level.
- **`arc-progress.js`** — the download progress line, built to pip's shape: fixed column order (label, bar, `done/total`, rate, `eta`), `━` with a `╸` leading edge, ASCII fallback outside Windows Terminal, ~8 redraws/second, and **no bar at all** when the size is unknown, because a bar without a denominator is a lie. It sheds columns before it sheds the bar (label → eta → rate) and never exceeds the terminal width. Silent without a TTY. Replaced `curl -#`, which showed a percentage and nothing else; the transfer moved into Node's `https` (`arc-update.httpDownload`) purely so the byte count is ours, with **curl kept as the fallback** for proxy and corporate-TLS cases. Related: `arc release` attaches a `git archive` of the tag as a release **asset**, because GitHub's generated `tarball_url` is served chunked with no `content-length` — measured — so only an uploaded asset makes a percentage possible at all.
- **`arc-verbosity.js`** — logs one row per reply (question chars, reply chars, whether it opened with a TL;DR) to `.arc/verbosity.jsonl`; read it back with `node src/arc-verbosity.js`. Written from the UserPromptSubmit hook and **deliberately silent** — it was built to inject a nag and the operator cut that, because the nag's supporting number was borrowed from `arc-comply`'s rule, not measured on this one. Baseline first. The log stores raw counts and no `wall` verdict: a threshold baked into the data can only ever confirm itself.
- **`arc-conv.js`** — pure conversation-id reconciliation, extracted from the runner so it unit-tests without launching claude.
- **`arc-duty.js`** — what a ROLE owns: the charter read/write layer (`duty` is a role fact; presence is a session fact).
- **`arc-help.js`** — builds the `arc` cheat sheet rendered by `/arc-help` (in-hook, zero tokens).
- **`arc-notify.js`** — Windows toast when a session finishes a non-trivial turn, labeled with its `/rename` name. Toasts on three events only: `Stop` (turn ≥30s, tune with `ARC_NOTIFY_MIN_MS`), `StopFailure` (always), and `Notification` (permission prompts only). Four cases are silent because the stop is not really a stop: a turn under the floor, a hand-off to background work, a compaction pause, and — added 2026-08-07 — **a turn with a board note still undelivered**. That last one was the operator's catch: `arc-stop-hook` is wired ahead of this script on `Stop` and blocks the stop to hand the note over, so the session goes straight back to work while the toast said "ready". Measured at 29 of 224 toasts (13%). The guard is a read-only `badge()` check rather than a marker file the stop-hook writes, so it does not depend on Claude Code running Stop hooks in order; and it returns **before** the turn clock is consumed, so the real completion still reports the whole turn.
- **`arc-platform.js`** — the remaining OS touchpoint (clipboard); the POSIX helpers died with cross-platform support.
- **`arc-setup.js`** — the interactive first-run wizard that writes `~/.claude/arc-config.json`.
- **`arc-stance.js`** — the per-session initiative dial (`/arc-mode passive·balanced·active`) for arc's agent-facing tools.

## Testing conventions

`test/run.js` runs every test against a throwaway `HOME` (`mkdtemp` under the temp dir), set **before** any `src` module loads (config computes `~/.claude` at load time). No interactive `claude`, no network (a `*_NO_REFRESH` env var stubs usage fetches). CI runs `windows-latest`. Section 7 exercises the real Windows key path (a DPAPI round-trip via `powershell.exe`) and the junction path; keep everything else OS-portable so the suite at least loads on any box. `CORE` failures fail the build; `PROBE` is informational.
